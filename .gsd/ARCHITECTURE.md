## Data Flow

1. **User Authentication:** Client calls `POST /api/auth/login` or `register` on Node.js backend. User role (`STUDENT`) is assigned server-side; JWT token returned and stored in client.
2. **Media Connection:** Client initiates mediasoup transport handshake via Socket.IO (`createWebRtcTransport`, `connectWebRtcTransport`, `produce`). SFU forwards audio/video streams to other peers.
3. **Live Transcription:** Instructor's client slices audio every 3–5 seconds and sends chunks to `unifiedSttServer.js` (port 5000). Active provider (Gemini or OpenAI or Mock) transcribes and emits `transcriptSegment` events, which are synchronized to SQLite.
4. **Snapshot OCR & Visual Analysis:** Instructor shares board or screen. Frame is captured, hashed (SHA-256), and analyzed via `visionService.js`. Extracted formulas and diagrams are saved in SQLite.
5. **Post-Lecture Synthesis:** When the lecture ends (`POST /api/lectures/:id/end`), backend triggers summary generation, study note synthesis (with vector SVG graphs), quiz generation (answers withheld from students), and SALKG graph verification.
6. **Student Review:** Students access `PostLectureHub.jsx`. All SVG elements are passed through DOMPurify; unauthorized students are blocked from private lectures.

## Conventions

**Security:**
- Defense-in-depth: Route authentication (`authenticateToken`), role check (`requireRole`), and object ownership check (`host_id === user.id || role === 'ADMIN'`).
- Input validation: Mathematical expressions whitelisted; subprocess arguments checked with regex `/^[a-zA-Z0-9_\-]+$/`.
- Safe rendering: All SVGs sanitized with `DOMPurify.sanitize(svg, { USE_PROFILES: { svg: true } })`.

**Database:**
- SQLite with `PRAGMA foreign_keys = ON;` enforced on every connection.
- All queries parameterized (`?` placeholders) — zero string interpolation in SQL.
